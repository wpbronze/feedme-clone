# 변환 결과 저장과 저장 목록

로그인한 사용자가 변환 결과를 저장하고, 저장 목록에서 다시 열어 보고, 필요 없으면 지울 수 있게 합니다.

## 연결된 소스

- [docs/specs/url-to-markdown/spec.md](../url-to-markdown/spec.md): 변환·내보내기 화면의 기준입니다. 이 스펙은 그 화면에 저장 동작을 더합니다. 해당 스펙의 "변환 이력 저장, 계정은 범위 밖"과 "프롬프트는 저장하지 않음"은 이 스펙이 계정 기반 저장을 추가하면서 대체합니다. 프롬프트를 저장하지 않는다는 규칙은 그대로 유지합니다.
- [docs/decisions/ui-composition.md](../../decisions/ui-composition.md): 새 화면(저장 목록, 저장한 글 보기)의 구성, 상태 설계, 반응형 기준입니다.
- [GLOSSARY.md](../../../GLOSSARY.md): 변환 결과, 저장한 글, 저장 목록의 정의입니다.
- 기존 로그인과 소유자 전용 접근 방식(`profiles`)을 따릅니다. 새 데이터도 같은 방식으로 본인만 읽고 쓸 수 있어야 합니다.

## 사용자에게 보이는 결과

1. **저장.** 변환 결과가 있으면 결과 화면에서 "저장" 버튼을 누를 수 있습니다. 로그인한 사용자가 누르면 그 결과가 저장한 글로 보관되고, 저장됐다는 피드백이 보입니다. 변환 결과가 없을 때는 버튼이 비활성화됩니다.
2. **같은 주소를 다시 저장.** 이미 저장한 URL을 다시 저장하면 새 항목을 만들지 않고 기존 항목을 최신 내용과 저장 시각으로 갱신합니다.
3. **비로그인 사용자.** 저장 버튼은 보이지만, 로그아웃 상태에서 누르면 화면 이동 없이 결과 아래에 "로그인하면 저장할 수 있습니다" 안내와 로그인 링크만 나옵니다. 화면의 변환 결과와 복사·다운로드 등 기존 동작은 그대로 유지됩니다.
4. **저장 목록.** 로그인한 사용자는 헤더의 링크로 저장 목록에 들어갑니다. 본인이 저장한 글만 최근 저장 순으로 보이고, 각 항목에는 제목, 저자(있을 때), 사이트, 저장 시각이 나옵니다. 저장한 글이 없으면 빈 상태 안내가 나옵니다. 로그인하지 않고 이 화면에 들어가면 로그인 페이지로 보냅니다.
5. **다시 보기.** 목록의 항목을 열면 저장 당시의 제목, 저자, 렌더링된 Markdown 본문을 볼 수 있고, 원문 페이지로 가는 링크가 있습니다.
6. **삭제.** 목록의 각 항목에서 삭제할 수 있습니다. 실수를 막기 위해 삭제 전에 확인을 거치고, 삭제하면 목록에서 바로 사라집니다.

## 승인된 범위

- 저장한 글에는 원본 URL, 제목, 저자, 사이트, Markdown 본문, 저장 시각이 들어갑니다. 프롬프트와 직접 입력한 문장은 저장하지 않습니다.
- 저장, 목록, 다시 보기, 삭제까지가 범위입니다.
- 저장 목록은 새 화면으로 만들고, 헤더의 로그인·설정 링크 옆에 진입 링크를 둡니다.

## 수용 기준

1. 로그인 상태에서 변환 후 저장하면 저장 목록에 그 글이 나타나고, 새로고침해도 남아 있습니다.
2. 같은 URL을 두 번 저장해도 목록에 한 항목만 있고, 저장 시각이 갱신됩니다.
3. 로그아웃 상태에서 저장을 누르면 저장되지 않고, 이동 없이 로그인 안내가 나오며 변환 결과는 화면에 남아 있습니다.
4. 한 사용자의 저장 목록과 저장한 글 보기에는 다른 사용자의 글이 나오지 않으며, 다른 사용자의 글 주소를 직접 열어도 볼 수 없습니다.
5. 저장한 글을 열면 저장 당시의 제목, 저자, 본문이 보이고, 원문 링크가 원본 URL로 연결됩니다.
6. 삭제를 확인하면 목록에서 사라지고 새로고침해도 돌아오지 않습니다. 확인을 취소하면 그대로 남습니다.
7. 저장 목록이 비어 있으면 빈 상태 안내가 보이고, 목록을 불러오는 중과 불러오기 실패 상태도 각각 구분되어 보입니다.
8. 저장에 실패하면(네트워크 오류 등) 이해할 수 있는 오류 안내가 보이고 변환 결과는 유지됩니다.
9. 라이트·다크 모드와 좁은 화면에서 새 화면과 저장 버튼이 읽을 수 있게 보이고 버튼이 숨겨지지 않습니다.

## 확정된 제약과 근거

- **비로그인은 안내만 보여준다.** 로그인 페이지로 이동하면 화면의 변환 결과가 사라져 사용자가 다시 변환해야 하므로, 이동 없이 안내만 합니다. 사용자가 선택한 방식입니다.
- **삭제를 이번 범위에 넣는다.** 지울 방법이 없으면 잘못 저장한 글이 목록에 계속 쌓입니다. 사용자가 선택했습니다.
- **저장한 글은 저장 시점의 사본이다.** 원본 페이지가 사라지거나 바뀌어도 저장한 내용을 다시 볼 수 있어야 하기 때문입니다.
- 소유자만 읽고 쓸 수 있다는 규칙은 화면이 아니라 데이터 접근 단계에서 지켜져야 합니다(수용 기준 4).
- UI는 [ui-composition](../../decisions/ui-composition.md)을 따라 shadcn 구성과 semantic token으로 만들고, 로딩·빈·오류 상태를 정상 화면과 함께 설계합니다.

## 가정(바꿔도 되는 기본값)

- 같은 URL의 판단은 사용자 단위로 합니다. 다른 사용자가 같은 URL을 저장해도 서로 영향이 없습니다.
- URL이 달라도 같은 글이면(쿼리 문자열 차이 등) 별개 항목으로 둡니다. URL 정규화는 하지 않습니다.
- 목록은 한 번에 모두 보여줍니다. 페이지 나누기, 검색, 정렬 변경은 없습니다.
- 저장한 글 보기에는 복사·다운로드·LLM 전달 같은 내보내기를 두지 않습니다.
- 저장 목록과 저장한 글 보기는 프로토타입 없이 기존 화면의 구성을 따라 만듭니다.

## 범위 밖

- 저장한 글의 제목 수정, 태그, 폴더, 검색, 페이지 나누기, 공유.
- 저장한 글에서 내보내기(복사·다운로드·ChatGPT·Claude로 열기).
- 로그인 후 변환 결과를 이어서 저장하는 흐름.
- 여러 기기 간 실시간 동기화, 오프라인 접근.
- 서버 속도 제한, 저장 용량 제한 등 보안 하드닝(스펙이 요구하지 않음).

## 남은 위험

- 프로토타입 없이 새 화면을 만들기 때문에 목록과 보기 화면의 모양은 구현 후 처음 확인됩니다. 어색하면 그때 조정합니다.
- 본문이 매우 긴 글을 저장하면 목록이나 저장 요청이 느려질 수 있습니다. 용량 제한은 두지 않습니다.
- 로그인 후 결과를 이어서 저장하지 못하므로, 비로그인 사용자가 로그인했다가 다시 변환해야 하는 불편이 남습니다.
